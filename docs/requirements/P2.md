# Rebaz

## Project title:

Rebaz, a collaborative travel planning and itinerary organizer web app.

## Problem statement:

During trip planning, travelers spend a substantial amount of time figuring out the trip destination, managing budgets, and keeping everyone on the same page.

## Objectives:

- O1: Let a trip organizer assemble a complete itinerary for a 5-day trip, including transport and lodging.

- O2: Show every member of a trip in the current plan, including changes in realtime.

- O3: Detect and report 100% of time overlapping itinerary items on the same day at the same moment an item is added.

- O4: Let a member export the full itinerary, to use without a network connection in no more than 3 actions.

- O5: Show each member who owes what and to whom, calculated from recorded expenses.

## Scope:

### In scope:

1. **Account registration, login, logout, deletion**

2. **Creating trips and inviting members via email.**

3. **Adding, removing, editing itinerary items with date and time.  Different item categories such as transport, lodging, and activities.**

4. **Viewing a shared itinerary and getting realtime updates upon changes.**

5. **Automatic detection of conflicting dates, times, and schedules.**

6. **Recording full expenses with equal splitting, and per member balances.**

7. **Export of itinerary to printable offline file.**

8. **Destination search, notes, links, check-in, bookings**

### Out of scope:

1. **Offering real bookings and payments inside the webapp.**

2. **Flight tracking/checking.**

3. **Insurance management.**

4. **Native mobile apps.**

## Stakeholders:

Trip organizer, Trip member, Touring agencies, product owners, scrum masters, development team.

## Feasibility check:

Useful: Yes.

Buildable by a team of four in about ten weeks: yes, provided it stays a responsive web app with manually entered content, one currency per trip and equal expense split.

Integration: no external dependency we cannot access. It needs a web host, and a database.

Optional sign-in with a Google or GitHub account can be dropped without losing a Must requirement. No paid travel API is required.

## Stories with acceptance criteria

### US-01 (Must), Set destination. As a user, I want to search for a city name and see what's available to plan my trip.

- AC1: Given when I am not logged in, when I type a city name the app displays the city name, country, and image.

- AC2: Given when a search returns no matching results, then I see “No destination found".

### US-02 (Must), Create a trip

- AC1: Given that I am logged in, when I enter a destination, a start and end date, the app should validate all the input. If all non-optional fields are all filled then the create trip button should get enabled.

- AC2: Given that I have input a start and end date, when I press on create trip, it should create the trip and show the trip in the “My Trips” section.

### US-03 (Must), Invite members. As a trip organizer, I want to invite people by messages, so that we all work from the same plan.

- AC1: Given that I am the organizer, when I send an invite link to someone, they receive it within a few seconds with all the details.

- AC2: Given when I invite the same member twice, it shows that they are already a member.

### US-04 (Should), See changes from members. As a trip member I want to be able to see who changed what.

- AC1: Given when a member edits an item, I should see the changes in realtime.

- AC2: Given when a member deletes an item, it is removed and the deletion is listed in the change log.
